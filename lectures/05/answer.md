### 変更と比較条件

資料を1ページだけ取得しても、LoRAとQLoRAの違いを説明できるかを調べた。変更したのは `app/config.py` の `RAG_TOP_K` だけで、通常のベクトル検索の上限を5件から1件にした。

質問は「第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？」。両条件とも `gemini-3.5-flash-lite` と、教材に同梱された第1〜3回の本講義214ページの検索DBを使った。同じ質問を `uv run python -m app.agent --trace "$AIE_QUESTION"` で各1回実行した。

### 実行結果

| 比較項目 | 変更前（上限5件） | 変更後（上限1件） |
|---|---|---|
| 呼び出したツールと回数 | `search_materials` を1回 | `search_materials` を1回 |
| ツールに渡した検索語 | `LoRA QLoRA 固定 学習` | `LoRA 固定 学習 QLoRA 加える` |
| ツールの戻り値の先頭 | `lec02-main-p052` | `lec02-main-p052` |
| 回答の引用箇所 | 第2回・PDF p.51、p.52 | 第2回・PDF p.52 |
| 回答完了まで | 3.35秒 | 2.89秒 |
| 入力／出力トークン数 | 3,027／202 | 1,191／186 |
| モデル応答回数 | 2回 | 2回 |
| 生成API推定費用（埋め込み・索引構築を除く） | 0.001413 USD | 0.000822 USD |

どちらの回答も、LoRAは元の重みを固定して差分を表す小さな行列A・Bだけを学習し、QLoRAは元の重みをさらに4ビットに量子化すると説明した。教材本文を照合すると、p.51は両手法の比較、p.52は固定する重みWと学習する行列A・Bを示す図解だった。変更後に引用されたp.52だけで、質問の三つの要点をすべて確認できた。

### 気づきと限界

検索上限を1件にすると、今回の入力は1,836トークン（60.7%）減り、回答の要点は保たれた。引用が1ページに減った理由は、そのページに必要な説明がそろっていたためと考えられる。一方、同じ質問でもモデルが作った検索語は少し違った。各条件1回の測定なので、0.46秒の時間差が検索件数だけで生じたかは判断できない。根拠が複数ページに分かれる質問でも1件で足りるかは、今後の比較課題である。
